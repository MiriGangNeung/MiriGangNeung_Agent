# 프롬프트 버전 이력

프롬프트 본문은 `prompts/*.md`에 있다. 이 파일은 무엇이 왜 바뀌었는지의 요약이다.
버전을 올릴 때는 기존 파일을 수정하지 말고 새 파일을 추가한 뒤
`app/pipeline/prompt.py`의 `PROMPT_VERSION`을 올린다. `promptVersion`은 백엔드가
생성 이력(E9)에 기록하는 값이므로, 프롬프트가 바뀌었는데 버전이 그대로면 과거
생성물과 구분이 안 된다.

## v3 (2026-08-22)

- `composition_v3.md` — 사용자 요청("좀 더 인스타 감성에 맞게, 사람의 포즈와 표정까지
  바꿀 수 있게")에 따라 v2 대비 두 가지를 바꿨다:
  1. **새 `## Pose and expression` 섹션** — 이전에는 "Identity preservation" 절이 사실상
     원본 사진의 포즈·표정을 그대로 베끼도록 유도했다(체형/외모 보존만 명시했을 뿐 포즈·
     표정 변경 허용은 없었음). 이제 동일 인물임을 유지하는 선에서 장면에 맞는 자연스러운
     포즈(약간의 몸 틀기, 걷는 모습, 풍경을 바라보는 모습 등)와 표정(자연스러운 미소 등)
     변경을 명시적으로 허용한다.
  2. **새 `## Aesthetic direction` 섹션** — 인스타그램 감성의 여행 사진 톤(살짝 따뜻한
     색보정, 깊은 하늘·바다색, 중앙 정렬보다 3분할 구도 선호)을 지시하되, "실제 사진처럼
     보여야 한다"는 제약(일러스트/과도한 필터 금지)을 같이 명시해 §3-4(과도한 보정으로
     인한 신원 오인 리스크)와 충돌하지 않게 했다.
  - `## Identity preservation`은 "동일 인물로 명확히 알아볼 수 있어야 한다"는 원칙은
    그대로 유지 — 포즈·표정은 바뀌어도 신원(얼굴 생김새·의상·체형)은 그대로다.
  - 나머지(장면 통합, 재생성 변형, 하드 제약)는 v2와 동일.
- 이 변경으로 이후 모든 생성물의 `promptVersion`이 `v2`에서 `v3`로 바뀐다.

## v2 (2026-08-15)

- `composition_v2.md` — v1에 `## Regeneration variation` 섹션과 `{variation_direction}`
  플레이스홀더를 추가했다. 요구사항 E4("사용자는 허용된 횟수 내에서 구도나 분위기를 변경해
  다시 생성할 수 있어야 한다")와 UI 설계서 재생성 버튼의 두 옵션("다른 배경 선택" / "구도,
  스타일만 살짝 조정") 중 후자가 이전까지 프롬프트에 반영되지 않아 새로 추가했다. 새 요청
  필드 `variationMode`(`same`|`new_pose`|`new_mood`)에 따라 `app/pipeline/prompt.py::
  _variation_direction()`이 이 자리에 지시문을 채운다. 나머지 섹션(정체성 보존, 장면 통합,
  하드 제약)은 v1과 동일하다.
- 이 변경으로 이후 모든 생성물의 `promptVersion`이 `v1`에서 `v2`로 바뀐다 —
  `variationMode`를 쓰지 않는(=`same`) 요청도 포함. 프롬프트 로직 자체가 바뀌었으므로
  E9 생성 이력 추적을 위해 버전을 함께 올렸다.

## v1 (2026-08-09)

- `composition_v1.md` — 인물+배경 합성. 얼굴/의상/체형 동일성 보존을 최우선으로
  명시하고, 조명·그림자·원근 일치를 요구. 배경 카탈로그의 `sceneHint`/`lightingHint`와
  B6 스타일 태그(신뢰도 0.4 이상만)를 주입한다.
- `quality_check_v1.md` — 출력 안전성·품질 판정. `person_count`, `face_natural`,
  `anatomy_correct`, `harmful_content`, `severe_artifacts`를 JSON으로 강제.
- `style_analysis_v1.md` — 의상/색상/무드/포즈/배경 적합도를 카테고리당 1개씩,
  한국어 짧은 문구 + 신뢰도로 추출.

초기 버전이라 이전 버전과의 비교 대상 없음.
